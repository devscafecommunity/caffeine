# 7.5 — GPU Compute (Noise + Erosão)

> **Fase:** 11 · **Prioridade:** Baixa · **Esforço:** Alto
> **Depende de:** Fase 5 (RHI GPU), 7.1 (algoritmos CPU de referência)
> **Quando fazer:** Resolução ≥ 513² ou erosão > 100 iterações com FPS aceitável em CPU

---

## Objetivo

Mover geração procedural pesada (noise fBm, erosão hídrica) para **compute shaders**, reduzindo tempo de Generate Terrain de segundos para milissegundos em heightmaps grandes.

---

## Escopo Inicial

| Algoritmo | GPU | CPU fallback |
|-----------|:---:|:--------------:|
| fBm noise (todas as variantes) | ✅ | ✅ |
| Domain warp | ✅ | ✅ |
| Thermal erosion | ✅ | ✅ |
| Hydraulic erosion | ⚠️ Parcial | ✅ |
| Auto splat | ❌ v1 | ✅ |
| Fault lines / cliffs | ❌ v1 | ✅ |

---

---

## Pipeline Compute

```
1. Upload heightmap inicial (flat ou seed buffer)
2. Dispatch noise.comp  (workgroup 8×8)
3. Dispatch warp.comp   (opcional)
4. Loop N: erosion.comp
5. Readback ou usar buffer direto para mesh generation
```

### Evitar readback

Ideal: **mesh generation também no GPU** (geometry shader / tessellation) — fase futura.

Mínimo viável: readback só após geração completa → `TerrainHeightmap::heights()` para `TerrainMeshBuilder`.

## Critérios de Aceitação

- [ ] Noise fBm GPU produz resultado visualmente similar ao CPU (tolerância ±2%)
- [ ] 257² generate < 100 ms em GPU dedicada
- [ ] Fallback CPU automático se compute indisponível
- [ ] Sem leak de buffers GPU no shutdown (corrigir UAF em `TerrainGpuTextures` primeiro)

---

## Riscos

- Divergência CPU/GPU entre plataformas (SPIR-V vs DXBC)
- Debug mais difícil — manter path CPU sempre funcional
- Readback stall — perfil com timestamp queries
